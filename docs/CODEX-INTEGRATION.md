## Scope, performance and privacy

Each observation samples HEAD, branch, scoped index entries, bytes of the explicit component inputs, root AGENTS.md, Cargo metadata and the roadmap twice. It rejects disagreement and redirected inputs. These are scoped fingerprints, not repository-wide snapshots. Unknown dependencies, nested instructions, changes reverted between samples, and arbitrary files outside the listed scope need separate inspection. SQLite transactions keep at most 256 session/component rows in the worktree-specific Git directory. Scope, event enums, revision hashes and hashed identifiers are stored. File contents, commands and conversation history are excluded. Missing files and absent checkpoints are distinct states. A corrupt database yields an error. Dormant mode has no worker, hook, model request or polling.

Release provenance is opt-in via the build wrapper. It records the default local locked release binary, compiler identity, worktree, HEAD and a fingerprint of the enumerated Cargo and Rust inputs before and after the build. It does not attest the OS, external toolchain installation, transitive native build inputs or already running processes. In a development checkout list_skills requires matching build provenance and holds the executable open against replacement through registry execution. Missing or stale evidence returns a compact rebuild instruction. Source-free installations retain their previous catalog semantics. Start the existing MCP launcher with -DeveloperTools to expose the optional read-only get_validation_evidence tool. No additional server registration is needed. One local status sample measured 424 ms and 252 UTF-8 payload bytes before the newline. No subscription or productivity estimate follows from this sample.

## Engineering memory

The native observer accepts remember with an exact topic, scoped component, kind, short decision or observation, primary reference, and up to five supporting scoped paths. Use the same workspace invocation as for checkpoints. For example, pass ObserverArgs containing remember, observer-pin, bridge, decision, the concise reason, tools/Invoke-DevObserver.ps1 and src/bin/reflex-observer.rs. Attach evidence already verified by the operator. The observer stores references and content digests. It does not infer a decision from an exit code or ingest a transcript.

Ask get_development_context for memory_topic on a validated worktree. Include since_commit for a bounded comparison against an ancestor. The result contains up to 16 relevant commit IDs, affected component paths, and explicit unknown ancestry if the base cannot be compared. The Revision Guard still owns optional remote freshness, branch and dirty-state checks. Routine recovery omits memory. No model call, GitHub connection, or background scan is needed for local recall.

Each repository stores at most 512 curated records in a SQLite database in the Git common directory. Removing a linked worktree leaves the records available as historical evidence. Ordinary recall is scoped by repository, worktree, branch, component and exact topic. With memory_history=yes, another worktree's record from the same branch may appear only as historical. Superseded decisions remain available within the four returned records. A current record must have compatible ancestry and unchanged declared dependencies. Changed decisions become stale, older experimental or performance results remain historical, and missing ancestry is uncertain. An explicit invalidation records a withdrawal with its own evidence. Creation and validation time refer to the operator's explicit record, and reads compute status again.

On the Windows fixture, a new observer process recalled the original decision after an unrelated commit in 664.7 ms, returning 818 UTF-8 bytes. Rechecking after a dirty dependency change took 469.1 ms. SQLite remained at 16384 bytes after the third record fit in existing pages. These single fixture observations do not predict long-term growth. The fixture also checks supersession, isolated worktrees and historical performance evidence. Branch purpose and release evolution are curated in Git. The bridge does not infer them automatically.
